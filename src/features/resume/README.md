# 독립 이력 페이지

`/resume`은 소개, 경력·프로젝트, 학력을 보여 주는 별도 페이지다. 각 프로젝트에서 Works 상세로 이동할 수 있다. 현재 검색 노출은 막고 sitemap에는 포함하지 않는다.

## 구성

- 소개 문단과 경력 두 묶음, 실무 프로젝트와 학력을 표시한다. 경력별 요약 목록은 생략하고 프로젝트 내용으로 바로 이어지며, 내부 구분선은 PC에서 오른쪽 본문에만 표시한다. 파티클 로고와 긴 자기소개서는 이 페이지에 표시하지 않는다.
- 경력 목차에서 소개·프리랜서·정규직·학력으로 이동한다. 프로젝트 상세를 보고 돌아올 때 해당 링크의 위치와 포커스를 복원한다. URL에 명시된 앵커는 우선한다.
- 데스크톱은 기간·소속과 경력 본문을 나란히 두고 왼쪽 정보를 오른쪽 정렬한다. 프로젝트별 기간·소속은 해당 프로젝트를 읽는 동안 고정하고, 정규직 프로젝트에는 반복 회사명을 생략한다. 모바일은 메타정보와 본문을 한 열로 표시한다.
- 공개 연락처는 이메일과 GitHub만 사용한다. 사진·전화번호는 사이트 데이터에서 제외한다.

## 데이터 관리

프로젝트 요약은 사용자가 제공한 실제 이력서의 9개 프로젝트·24개 업무 항목과 맞춘다. 자세한 구현 과정은 Works 상세에서 설명한다.

`data/generalResume.json`은 이웃 resume 저장소의 `getResumeVariant('general')`에서 공개 필드를 선택해 만든 뒤, 사이트에 맞는 역할·프로젝트 설명을 별도로 다듬은 정적 데이터다. 회사별 제출본이나 raw commonResume는 사용하지 않는다.

`node scripts/export-resume-content.mjs`는 원본을 수정하지 않지만 **현재 사이트의 JSON을 원본 기준으로 덮어쓴다.** 원본과 사이트의 역할·수치 표현이 다를 수 있으므로 내보내기 전 현재 JSON을 보존하고, 생성 결과를 비교해 사이트에서 확인한 내용을 다시 반영한다. 원본 위치가 다르면 데이터 디렉터리를 인수로 전달한다. 새 프로젝트가 추가되면 스크립트의 이름-라우트 매핑을 먼저 보완한다. 배포 빌드는 이웃 저장소에 접근하지 않는다.

## 검증 범위

- 공개 연락처, 경력·프로젝트 상세 연결 및 각 작업의 공개 범위
- 경력 목차, 상세 진입과 복귀 위치·포커스, 명시된 URL 앵커
- 모바일 줄바꿈과 가로 넘침, 모션 감소 환경
